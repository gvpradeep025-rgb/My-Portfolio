    Project 01

    Self-Healing Selenium Framework

    A Selenium + Java + TestNG framework that recovers when locators change, and refuses to continue when it can't be sure it found the right element.

    • Java
    • Selenium
    • TestNG
    • Maven
    • GitHub Actions
    Tests

    App versions

    Threshold
    0.80
    Read on GitHub ↗
    • Fallback order: name → aria-label → visible text → structural CSS.
    • Each candidate is scored 0–1 against a fingerprint (text .25, aria-label .20, name .15, placeholder .15, tag .15, type .10) using normalized Levenshtein.
    • Only one match at or above 0.80 is accepted.
    • Outcomes: PRIMARY_OK, HEALED, ELEMENT_MISSING, LOW_CONFIDENCE, AMBIGUOUS.
    • A bundled 4-version demo bank app includes a "Delete account" trap that reuses the login button's id. The framework detects it and never clicks.

    05 / Principles

    How I test.

    1. 01

      Refuse to guess.

      My self-healing locator stops instead of clicking when two elements match or confidence is low.

      SafetyTrapTest.java ↗

    2. 02

      Test the unhappy path first.

      Missing tokens, wrong passwords and malformed bodies get their own test class.

      BookingNegativeTest.java ↗

    3. 03

      Check the contract, not just the status.

      Responses are validated against JSON Schemas.

      booking-schema.json ↗

    4. 04

      Prove the database agrees.

      Integration tests compare what the API says with what was stored.

      test_application_workflow.py ↗

    5. 05

      Test the tests.

      Mutation checks weaken a business rule and make sure the suite fails.
